## 概要

習慣とタスクを記録するアプリ。続けると習慣ごとの「称号」が上がり、サボると錆びて下がる。Web版（GitHub Pages）とPWAは公開済みで、iOS版は Capacitor のプロジェクトまで用意済み（申請は岩崎さんの作業待ち。Xcode でのビルド・実機確認の記録は見当たらない）。コミット 58f7e8a 時点の内容。以後の変更は #0002 以降の文書に記録する。

## 仕様

### 画面と機能

**共通**

- 下のタブは「今日 / 統計 / 設定」の3つ。画面は `#s-today` `#s-stats` `#s-set`
- ヘッダー右のボタン（`#themeBtn`）でライト / ダークを切り替える
- 右下の＋（`#fab`）で習慣かタスクを追加する。今日タブにだけ出る
- 初回起動時は案内（`#obd`）を表示する。「はじめる」で `onboarded` を保存
- 保存データが無い初回は、見本の習慣を3つ入れる（`seedIfEmpty()`）。水分補給（1日8回）、運動（毎日）、読書（月〜金）
- 日付が変わると今日の表示に切り替わる。30秒ごとと画面復帰時に `tick()` が確認する

**今日タブ（`#s-today`）**

- 達成率のリング（`#ringFg`）と残り件数
- 「あなたは今」の帯（`#identStrip`）。称号の高い順に最大3つ。タップで統計タブの称号カードへ移動
- 休息チケットの案内（`#rescueBanner`）。昨日やらなかった習慣があると出る（条件は下の「休息チケット」）
- ひとこと（`#quoteBanner`）。時間帯のあいさつと日替わりの言葉（`QUOTES` 14個）
- 一覧（`#todayContent`）は「習慣」「タスク」「お休み中」の3区分
  - 右の丸をタップで達成。回数タイプは押すたびに +1。目標を超えて押すと 0 に戻る
  - カードをタップすると編集シートが開く
  - 長押し（約0.26秒）してドラッグで並べ替え（`startDrag()` `commitOrder()`）
  - 「お休み中」の再生ボタンで一時停止を解除
  - 全部達成すると紙吹雪（`celebrate()`）

**統計タブ（`#s-stats`）**

- 称号カード（`#tcard`）。上位3つの称号、習慣ごとの「次の称号まで残り◯日」（最大6件）、今月の休息チケット残数、共有ボタン
- 共有（`shareTitleCard()`）。1080×1350 の PNG を Canvas で作り、端末の共有機能（`navigator.share`）に渡す。使えない環境では `kotsu-title.png` をダウンロード
- レベルと XP バー
- 数字4つ。最長ストリーク、今日の達成率、直近7日の達成率、これまでの完了数
- この7日間の棒グラフ（`#weekChart`）
- 実績バッジ12種（`BADGES`）
- 月カレンダー（`#calGrid`）。日ごとの達成を点の色で表示（全達成=緑、一部=黄）。今日以前の日をタップすると日別記録シートが開く
- 習慣別の達成率。直近30日（週◯回タイプは直近4週）

**設定タブ（`#s-set`）**

- 毎日のリマインド。オン / オフ（`#remSwitch`）、時刻（`#remTime`、初期値 20:00）、テスト通知（`#remTest`）
- テーマ。ライト / ダーク / 自動（`#themeSeg`）
- バックアップを保存（`#exportBtn`）、バックアップから復元（`#importBtn`）
- すべてリセット（`#resetBtn`）。確認ダイアログ（`#cdlg`）のあと全削除し、見本の習慣を入れ直す
- 最下部の表記は「コツコツ v2 — 習慣＆タスク管理」

**追加・編集シート（`#sheet`）**

- 種類は「習慣 / タスク」（`#typeSeg`）
- 名前（最大24文字）、アイコン（絵文字16種 `EMOJIS`）、カラー（8色 `COLORS`）
- 習慣だけ: くり返し「毎日 / 曜日で / 週に◯回（1〜7）」、1日の目標回数（1〜20）
- タスクだけ: 期限（任意）。一覧に日付を出すだけ
- 編集時だけ: 一時停止スイッチ（習慣）、削除ボタン（`#delBtn`。記録日数を示して確認）

**日別記録シート（`#daySheet`）**

- カレンダーで選んだ日に予定されていた習慣を並べる。タップで達成 / 未達を切り替え
- 回数タイプは目標回数ぶんを一度に記録する
- 今日を除く直近7日以内なら「この日を休息日にする」ボタン（`#dayRestBtn`）が出る
- タスクは表示しない

**称号と錆び（`RANKS` `updateRanks()` `missedRun()` `rustLevel()`）**

| 段階 | 称号 | 毎日・曜日タイプ（連続日数） | 週◯回タイプ（連続週数） |
|------|------|------|------|
| 0 | 見習い | 0 | 0 |
| 1 | 入門者 | 3 | 1 |
| 2 | 常連 | 7 | 2 |
| 3 | 実践者 | 21 | 4 |
| 4 | 達人 | 50 | 8 |
| 5 | 師範 | 100 | 16 |
| 6 | 伝説 | 365 | 52 |

- 称号名は「習慣名 + の + 段階名」（例: 読書の常連）。`fullTitle()`
- 連続日数（ストリーク、`streak()`）が基準に届くと上がる。「称号を獲得！」のポップアップが出る
- 錆びの数は、昨日からさかのぼって予定日に続けて未達だった数。休息日と作成日（`createdAt`）より前は数えない
  - 毎日・曜日タイプ: 1回=くすみ、2〜3回=錆び、4回以上=失いかけ
  - 週◯回タイプ: 未達の週が1つでもあれば「失いかけ」
- 降格: 毎日・曜日タイプは未達5回ごと、週◯回タイプは未達2週ごとに1段階下がる。「称号が錆び落ちました」のポップアップが出る
- 「見習い」は錆びない
- 今日やれば錆びは消える。週◯回タイプは今週の目標を満たせば消える

**休息チケット（`useRestTicket()` `restTicketsLeft()` `canRestOn()`）**

- 月1枚。使った日はその日の全習慣がサボり扱いにならない。ストリークも称号も守られる
- 使える日は「今日を除く直近7日以内」
- 使う場所は2つ。今日タブの案内（昨日分だけ）と、日別記録シートのボタン
- 今日タブの案内が出る条件（`renderRescue()`）
  - 昨日が休息日でない
  - チケットが残っている
  - 昨日分で「そのまま」を押していない（`rescueSeen`）
  - 見習いより上の毎日・曜日タイプの習慣に、昨日の未達がある

**レベルと実績（`aggregate()` `levelInfo()` `BADGES`）**

- XP は完了数 × 10。レベル2 は 100XP、3 は 300XP、4 は 600XP、5 は 1000XP（`50×(L−1)×L`）
- 実績は12種。はじめの一歩 / 三日坊主卒業（3日連続）/ 1週間つづいた（7日）/ 習慣化マスター（21日）/ 1ヶ月の王者（30日）/ パーフェクト / 完璧な1週間 / 10回・50回・100回達成 / レベル5 / 継続の証（習慣5つ以上）
- 一度取った実績は、リセットしない限り消えない（`badges`）

**通知と触覚**

- Web版の通知: アプリを開いている間だけタイマーで確認する（`scheduleReminder()` `fireReminderIfDue()`）。時刻を過ぎて未完了があれば1日1回通知。開いた時点で時刻を過ぎていても通知する
- Web版の注意書き（`#remNote`）: iPhone は「ホーム画面に追加」した状態で iOS 16.4 以降が必要
- iOS版の通知: 端末のローカル通知を毎日その時刻に予約する（`nativeScheduleReminder()`、通知ID 1001）。文面は固定で「今日の習慣、わすれてない？」
- 触覚（`haptic()`）: iOS版は Capacitor Haptics。Web版は `navigator.vibrate`（対応端末だけ）

### データの保存

- 保存先は localStorage。キーは `kotsu_v1`（定数 `STORE_KEY`）。状態全体を JSON 文字列で1件に保存する
- iOS版は同じキー・同じ JSON を Capacitor Preferences（ネイティブ保存）にも書く（`save()`）
- iOS版は起動時に `hydrateFromNative()` がネイティブ保存を読む。記録数（`recordCount()`）が localStorage より多ければ置き換え、「データを復元しました」と表示
- データを読むときは `normalize()` が足りない項目を補う

**状態（`state`）の中身**

| キー | 内容 |
|------|------|
| `items` | 習慣・タスクの配列（下表） |
| `theme` | `"light"` / `"dark"` / `null`（自動） |
| `reminder` | `{enabled, time:"HH:MM", lastNotified:"YYYY-MM-DD"}` |
| `badges` | 取得した実績の id の配列 |
| `rest` | 休息日。`{"YYYY-MM-DD": true}` |
| `restUsed` | 月ごとのチケット使用数。`{"YYYY-MM": 数}` |
| `rescueSeen` | 休息チケットの案内で「そのまま」を押した日 |
| `onboarded` | 初回案内を見たか |
| `_seeded` | 見本データを入れたか |

**`items` の1件**

| キー | 内容 |
|------|------|
| `id` | `"i" + 時刻 + 乱数`。見本は `seed1`〜`seed3` |
| `name` / `emoji` / `color` | 名前・絵文字・色 |
| `type` | `"habit"`（習慣）/ `"task"`（タスク） |
| `repeat` | `"daily"` / 曜日番号の配列（0=日）/ `{w:N}`（週N回） |
| `target` | 1日の目標回数 |
| `due` | タスクの期限 `"YYYY-MM-DD"` か `null` |
| `paused` | 一時停止中か |
| `done` | 日付ごとの回数 `{"YYYY-MM-DD": 回数}`。タスクは `__done: true` も持つ |
| `order` | 並び順 |
| `createdAt` | 作成日 |
| `rank` / `rust` / `rustDrops` | 称号の段階 / 錆びの数 / 適用済みの降格回数 |

**バックアップ / 復元 / リセット**

- 保存: 状態全体を整形した JSON を `kotsu-backup-YYYY-MM-DD.json` としてダウンロード
- 復元: JSON ファイルを選ぶ。`items` が配列なら今のデータを丸ごと置き換える（合体はしない）
- リセット: localStorage とネイティブ保存の両方からキーを消す

### PWA・iOS

**PWA**

- `manifest.json`: 名前「コツコツ — 習慣＆タスク」、短い名前「コツコツ」、`start_url` は `./index.html`、`display` は `standalone`、縦向き、テーマ色 `#6C5CE7`、背景 `#f4f5f9`、アイコンは svg / 192 / 512
- `sw.js`: キャッシュ名は `kotsu-v6`。インストール時に `./` `./index.html` `./manifest.json` `./icon.svg` `./icon-192.png` を保存
- 取得はキャッシュ優先。無ければネットから取ってキャッシュに足す。ネットも無理なら `./index.html` を返す
- 登録は `index.html` の末尾。iOSアプリ内（`NATIVE`）では登録しない

**Web ファイルを iOS に入れる流れ**

1. `npm run sync-web`: `sync-web.sh` が `index.html` `manifest.json` `sw.js` `icon.svg` `icon-192.png` `icon-512.png` `apple-touch-icon.png` を `ios-app/www/` にコピー
2. `npx cap sync ios`: `ios-app/ios/App/App/public/` に反映
3. `npm run sync` は 1 と 2 をまとめて実行する

58f7e8a 時点で `ios-app/www/index.html` と `ios-app/ios/App/App/public/index.html` は本体の `index.html` と同じ内容（比較して確認）。

### 既知の制限・注意点

**README・文書との食い違い**

- iOS版のリマインド: README・設定画面・申請文面は「未完了があれば通知」。実装のローカル通知は毎日同じ時刻に固定文面で届き、未完了の有無を見ない（`nativeScheduleReminder()`）
- バージョン表記がそろっていない。画面下は「v2」、Xcode は 1.0、`package.json` は 1.0.0。コミット 9454f81 は称号機能を「v1.1」と呼び、README は HealthKit 連携を「v1.1」としている
- 引き渡し手順は「`pod install` は不要」とする。これは Dropbox 上のフォルダの場合。`ios-app/ios/App/Pods/` `ios-app/ios/App/App/public/` などは git 管理外なので、GitHub から取り直すと `npm install` と `npm run sync` が必要になる（未検証）
- README は「push すれば Web 版も同時に更新」とする。ただし `sw.js` はキャッシュ優先。`CACHE`（今は `kotsu-v6`）を変えないと、PWA として使っている人に古い画面が出続ける可能性がある

**コードから読み取れる制限**

- 一時停止の期間は記録していない。再開すると停止中の予定日が「未達」として数えられ、錆び・降格・ストリーク切れが起きる（`missedRun()` `streak()` は停止期間を見ない）。統計も、再開後は停止期間が未達扱いになる（`statDay()` は今の `paused` だけを見る）
- 完了したタスクは一覧から消える。元に戻す画面も、完了済みを見る画面も無い。期限は表示だけで、期限切れの知らせは無い
- 統計の「最長ストリーク」は過去最高ではない。今続いている連続数のうち最大の値。週◯回タイプの週数も「日」として表示され、実績（3日・7日…）の判定にも同じ値を使う
- 「パーフェクト」「完璧な1週間」は直近60日だけを数える
- 日別記録シートでは、回数タイプは目標回数ぶんを一度に入れる。途中の回数は入れられない
- テーマ「自動」は `applyTheme()` が呼ばれた時に OS の設定を読むだけ。使用中に OS 側を切り替えても、開き直すまで反映されない
- 休息チケットの枚数は「使う操作をした月」で数える（`monthKey()` は今日の日付を使う）
- 復元は `normalize()` を通さず、一部の初期値だけ補う。復元後に通知の予約（`scheduleReminder()` `nativeScheduleReminder()`）はやり直さない

**環境による差・未確認**

- iOS版のビルドと実機確認の記録は見当たらない。HealthKit メモによると、開発機（M1 MacBook Air / macOS 14.1.1）には Xcode を入れられない。以下は実機で未確認
  - `window.Capacitor.Plugins` 経由でのプラグイン呼び出し（JS パッケージは読み込んでいない）
  - localStorage が消えたときの復元。起動時は `seedIfEmpty()` が見本データを `save()`（ネイティブ保存にも書く）した後に `hydrateFromNative()` が読む順番。この場合に元のデータが戻るか要確認
  - アプリ内で、称号カードの共有（`navigator.share`）、バックアップのダウンロード、復元のファイル選択が動くか
  - iOS版でも Web 用の `fireReminderIfDue()` が動く。WebView に通知の仕組み（Notification API）が無い場合、時刻を過ぎて未完了があると「通知が許可されていません」のトーストが出る可能性がある
- Web版の通知は、アプリを開いている間と開いた時だけ届く
- 申請まわり: App Store 用スクリーンショット（6.7 / 6.5 / 5.5インチ）はフォルダ内に無い。プライバシーポリシーURLは引き渡し手順に記載が無い。v1.0 で必要かは未確認（HealthKit メモは v1.1 で新たに必要としている）。サポートURLはアプリ本体のページで、問い合わせ先の記載は無い
- `ios-app/node_modules/` と `ios-app/ios/App/Pods/` が Dropbox 内にある。共通ルール（`アプリ開発/CLAUDE.md` 5章）では、同期が重くなるため使い終わったら削除か選択型同期から外すことになっている
