## 結論

## 使うプラグイン

```bash
npm install capacitor-health@7.1.0
```

- `capacitor-health@7.1.0` は peerDependencies が `@capacitor/core >=7.0.0` で、本プロジェクト（Capacitor 7.6.9）にそのまま入る
- 最新の 8.x は Capacitor 8 が必要なので、**7.1.0 を指定すること**
- コミュニティ製（公式Capacitorプラグインではない）。2026年8月時点でメンテは活発

## 取得できるデータ

```ts
queryAggregated({ startDate, endDate, dataType, bucket })
// dataType: 'steps' | 'active-calories' | 'mindfulness'

queryWorkouts({ startDate, endDate, ... })
// ランニング・筋トレ等の種類と時間
```

| データ | 用途案 |
|---|---|
| steps | 「1日8000歩」習慣の自動達成 |
| active-calories | 運動量の表示・自動達成 |
| workouts | Apple Watchのワークアウトで「運動する」を自動達成 |
| mindfulness | 「瞑想」習慣の自動達成 |

## 実装方針

### 1. 習慣に「自動達成」の設定を追加
データモデルに `auto` を追加する案：
```js
it.auto = { source:'steps', goal:8000 }   // 歩数8000で自動達成
it.auto = { source:'active-calories', goal:300 }
it.auto = { source:'workouts', minutes:20 }
```

### 2. 判定タイミング
- アプリ起動時／フォアグラウンド復帰時（既存の `tick()` に相乗り）
- 取得した値が goal 以上なら `it.done[todayStr()] = it.target` を書き込む
- **手動チェックも従来通り可能にする**（自動はあくまで補助）

### 3. Web版との両立（必須）
既存の `NATIVE` 判定と同じ方式で分岐する。
```js
const HK = NATIVE && CAP.Health;
if(!HK){ /* 従来通り手動チェックのみ。UIの自動達成設定は隠す */ }
```
Web版（GitHub Pages）はHealthKitが無いので、**必ずフォールバックさせること**。

### 4. UI
- 編集シートに「自動で達成にする」セクション（習慣のみ・ネイティブのみ表示）
- ホームのカードに歩数バッジ（例: `👟 6,240 / 8,000`）
- 設定画面に「ヘルスケア連携」トグル＋権限の再要求ボタン（`openAppleHealthSettings()`）

## App Store申請で追加になる要件（重要）

HealthKitを使うと審査要件が増える。**v1.0の申請内容から変わる点**：

1. **プライバシーポリシーのURLが必須になる**
   - HealthKit使用アプリは免除されない
   - 現在はサポートURL（GitHub Pages）しかないので、**新規に用意が必要**
   - 内容: 健康データは端末内でのみ利用し、外部送信・収集しないことを明記

2. **Info.plist に使用目的の記載が必須**
   ```xml
   <key>NSHealthShareUsageDescription</key>
   <string>歩数や運動量を読み取り、習慣の達成を自動で記録するために使用します。データは端末内でのみ利用され、外部に送信されません。</string>
   ```
   （書き込みもするなら `NSHealthUpdateUsageDescription` も必要。今回は読み取りのみの想定）

3. **XcodeでHealthKit capabilityを有効化**
   - Signing & Capabilities → ＋Capability → HealthKit

4. **App Store Connectで健康データの取り扱いを申告**
   - 「データを収集しません」の申告内容を見直す必要あり
   - 端末内で完結し外部送信しないなら「収集なし」のままでよいが、要確認

5. 健康データを広告・マーケティングに使わないこと（App Store Review Guideline 5.1.3）

## テストについて（注意）

- **HealthKitはシミュレータではまともにテストできない**（ヘルスデータがほぼ空）
- **実機＋Xcodeが必須**
- 開発機（M1 MacBook Air / macOS 14.1.1）はXcodeを入れられないため、**実装者側で動作確認ができない**
- → 実機テストは Xcode環境を持つ担当者に依頼する前提で進めること

v1.0でビルド〜審査通過の流れを確立してから着手する。
